# AGENTS.md — правила работы с проектом

Краткий свод для агента/разработчика. Полная документация:
[`docs/architecture.md`](docs/architecture.md), аудит безопасности:
[`docs/security-audit.md`](docs/security-audit.md).

**Истина — в коде.** Если код и документ расходятся, верен код; документ нужно обновить.

---

## 1. Что это за проект

Веб-платформа онлайн-тестирования для технопарков «Кванториум».
Методист создаёт тест в конструкторе и публикует его по ссылке;
участник проходит **без аккаунта** (ФИО + номер сертификата ПФДО) и сразу видит результат;
методист смотрит попытки и выгружает их в Excel. Есть администратор.

Стек: FastAPI + MongoDB (pymongo async) + Vue 3 (Vite) + nginx.
Деплой — **единый Docker-образ** (frontend + backend + nginx), в т.ч. на Amvera.

---

## 2. Куда что класть

```
backend/
  models/     документы Mongo (Pydantic). id -> _id при сохранении
  schemas/    контракты API (что приходит/уходит по HTTP)
  routers/    только HTTP: пути, коды, Depends, response_model
  services/   вся бизнес-логика, проверки прав, работа с БД
  config.py   env (валидирует jwt_secret, admin_password)
  db.py       async-клиент Mongo, ensure_indexes()

frontend/online_test/src/
  api.js      ВСЕ запросы к API — только через него
  auth.js     состояние авторизации, restoreSession()
  components/ общие переиспользуемые компоненты
  constructor/ конструктор теста + редакторы по типам
  public/     прохождение теста по ссылке
  user/       логин, профиль, результаты
  admin/      админка
```

Направление зависимостей: `routers → services → models/db`; `schemas` — рядом.
Не тащить бизнес-логику в роутеры, а работу с `Request`/`Response` — в сервисы.

## 3. Не нарушать (зафиксированные решения)

1. **Model ≠ Schema.** `hashed_password` живёт только в `models/user.py`, наружу —
   `UserPublic`. Не отдавать хэш пароля никогда.
2. **Правильные ответы не уходят в публичный API.** `TestPublic`/`QuestionPublic`
   не содержат `is_correct`. Проверка только на сервере.
3. **UUID вопросов и ответов сохраняются** при редактировании теста
   (`Constructor.vue` → `uid(...)`). Пересоздание id рвёт связь с попытками.
4. **Попытка хранит снимок текстов** (`QuestionResult.text/given_texts/correct_texts`).
   Детали попытки читать из снимка, id — только fallback для старых записей.
5. **Опубликованный тест неизменяем:**
   - сервер: `update_test` → `409`;
   - фронт: `fieldset disabled` + серые кнопки + баннер;
   - профиль: кнопка «Редактировать» `disabled` при `status === 'published'`.
6. **Версионности нет** — сознательно. Не добавлять `version` без явной просьбы.
7. **Участник — без аккаунта.** Не тащить регистрацию в прохождение теста.
8. **Тест — один документ** со встроенными `questions` (embed). Отдельную коллекцию
   вопросов не делать.
9. **Медиа:** файлы на диске (`/data/uploads`), метаданные в `media`.
   Удалять файлы вместе с вопросом/тестом — хранилище ограничено.
10. **Единый Docker-образ.** Amvera не поддерживает compose; `docker-compose.yml`
    только для локальной разработки.

## 4. Секреты и безопасность

- **`.env` не читать и не печатать.** Пароли, токены и ключи не выводить в переписку.
- Пароли — только bcrypt (`security.hash_password`), никогда в открытом виде.
- JWT — в HttpOnly-cookie; в JS токен недоступен. Не «пробрасывать» его во фронт.
- Новые проверки доступа — через `get_current_user` / `require_admin`.
- Валидация пользовательского ввода — в `schemas/`, сообщения на **русском**.
- Загрузка файлов: проверять по **содержимому** (Pillow), не по расширению;
  лимит 5 МБ; без SVG; имя файла генерировать, не доверять присланному.

---

## 5. Стиль кода

- Type hints везде (`def f(x: int) -> str`). Для `str | None` — Python 3.12 синтаксис.
- Комментарии и сообщения API — **на русском**.
- Комментарий — объясняет «почему», а не «что» (код и так читается).
- Не оставлять `console.log` / отладочные `print` в коде.
- В Vue — `<script setup>`, Composition API. Не переводить на Options API.

```bash
cd backend
python -c "import ast,pathlib;ast.parse(pathlib.Path('main.py').read_text(encoding='utf-8'))"
```

```bash
cd frontend/online_test
npm run build
```

Оба должны проходить **до** отчёта о завершении. Если падают — починить, не сдавать.

## 7. Деплой и запуск (кратко)

Полная версия — в `docs/architecture.md`, раздел 13.

```bash
# Локально (Mongo на хосте)
docker build -t online-test .
docker run -d --name online-test -p 8080:80 \
  --env-file .env -e mongo_host=host.docker.internal -e mongo_port=27017 \
  -v online_test_media:/data/uploads online-test

# Проверка подключения к БД без запуска сервиса
docker run --rm --env-file .env -e mongo_host=host.docker.internal online-test \
  python -c "import db,asyncio;asyncio.run(db.test_db())"
```

На Amvera `/data` — постоянный диск платформы; volume локально нужен, там — нет.
